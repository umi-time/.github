# Contributing to Umi‑Time

Umi‑Time is an open standard for solar‑aligned civil timekeeping, along with reference implementations and documentation.  
Contributions are welcome across all repositories in the organization.

This document explains how contributions work at the organization level.  
Each repository also includes its own repo‑specific `CONTRIBUTING.md` with technical details.

---

## Repositories

The Umi‑Time project is split into three public repositories:

- **spec** — The Umi‑Time Standard (CC‑BY‑4.0 license)  
- **umi-time-js** — The official TypeScript reference implementation (MIT license)  
- **www** — The documentation website and demos (MIT license)

Please consult the `CONTRIBUTING.md` inside each repository for instructions specific to that codebase.

---

## Discussions

The **spec** repository is the only Umi‑Time repository with GitHub Discussions enabled.

Use Discussions when you want to:
- Ask questions about the standard  
- Propose ideas or conceptual changes  
- Explore design considerations  
- Request clarification on definitions or algorithms  

All technical implementation questions should be opened as issues in the relevant code repository (e.g. `umi-time-js` or `www`).

---

## How to Contribute

### 1. Open an Issue
Issues are the preferred way to report bugs, request features, or propose changes.

When opening an issue, please include:
- Clear description of the problem or proposal  
- Reproduction steps (if applicable)  
- Expected vs actual behavior  
- Environment details (browser, OS, Node version)  
- Any relevant Umi‑Time input values  

### 2. Submit a Pull Request
Pull requests should be:
- Small and focused  
- Well‑documented  
- Linked to an issue when appropriate  
- Passing all tests and build steps  
- Consistent with the style and architecture of the target repo

All PRs require review before merging.
